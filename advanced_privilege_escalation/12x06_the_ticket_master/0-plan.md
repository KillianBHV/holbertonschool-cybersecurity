To evaluate the path to Thornbury’s database server through the domain's identity infrastructure, this engagement plan establishes an objective, metrics-driven authorization assessment framework.

Material Utility and Non-Plaintext Authorization Assessment
Recovered authentication material has a strictly defined use centered on verifying its intrinsic authorization utility within the enterprise directory environment. For captured material where a plaintext password is not recovered, its utility is determined by assessing whether the cryptographic asset independently supports a valid, authorized authentication path. We thoroughly analyze the material to see if the identity's existing domain groups, nested roles, and specific delegation paths possess legitimate structural relationship alignment with the target database server. Non-plaintext assets, such as hashes or tickets, are carefully evaluated to confirm if they provide sufficient cryptographic validation to map a path, rendering plaintext translation entirely unnecessary for verifying administrative authorization status.

Cracking Evaluation and Resource Thresholds
We execute a selective cracking strategy where each recovered hash is subjected to an explicit cost-benefit test before any cracking time is allocated. Material is prioritized based on a calculated ratio where the identity’s probable path to Thornbury's database server represents the expected value, and the password entropy represents the expected effort. We only crack material when the likelihood of gaining direct database access outweighs the estimated cracking time. A hash is skipped entirely if its access value is low while its estimated cracking effort is high. We continuously reassess cracking effort against remaining engagement hours, stopping or reprioritizing our focus to mitigate diminishing returns whenever the expected access value no longer justifies the ongoing resource allocation.

Domain Controller Records and Analytical Scope
We anticipate that prior to any active assessment step, the Domain Controller records standard telemetry through Kerberos Authentication Service and Ticket Granting Service event logging, specifically tracking Event IDs 4768 and 4769. The client’s Security Operations Center will reconstruct our engagement from these exact artifacts. To maintain a non-disruptive, controlled scope, a strict constraint is established: we will not interact with or target the Domain Controller itself. The entire objective remains framed strictly as an identity relationship problem, focusing on how authorization paths are structured within the domain. This methodological focus ensures a clean validation of existing access pathways without modifying system configurations or introducing operational risks to the actuarial services.
