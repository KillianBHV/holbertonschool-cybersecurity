# Engagement Plan
To evaluate the path to Thornbury’s database server through the domain's identity infrastructure, this engagement plan establishes an objective, metrics-driven authorization assessment framework.

## Material Utility and Non-Plaintext Authorization Assessment
Recovered authentication material has a strictly defined use centered on verifying its intrinsic authorization utility. For captured material where a plaintext password is not recovered, its utility is determined by assessing whether the cryptographic asset independently supports a valid, authorized authentication path. We thoroughly analyze the material to see if the identity's existing domain groups, nested roles, and specific delegation paths possess legitimate structural relationship alignment with the target database server. Non-plaintext assets, such as hashes or tickets, are carefully evaluated to confirm if they provide sufficient cryptographic validation to map a path, rendering plaintext translation entirely unnecessary for verifying administrative authorization status.

## Cracking Evaluation and Resource Thresholds
We enforce a concrete decision model to select specific recoverable material for cracking based on a clear efficiency ratio. We mathematically divide an identity's expected access value by its estimated processing cost. The expected value is mapped into three explicit priority tiers: Tier 1 signifies direct access to Thornbury’s database server, Tier 2 signifies path access via domain group delegation, and Tier 3 signifies isolated local access. We prioritize Tier 1 and Tier 2 assets over Tier 3 assets. Cracking time is strictly budgeted at a maximum threshold of forty-five minutes per hash. We will reassess cracking effort when the expected value no longer justifies the remaining engagement hours, and stop or reprioritize accordingly to mitigate diminishing returns. Our definitive stopping rule dictates that processing ceases immediately if the password entropy calculation exceeds sixty bits of complexity, or if a concurrent, lower-cost Tier 1 path is established.

## Domain Controller Records and Analytical Scope
We anticipate that prior to any active assessment step, the Domain Controller records standard telemetry through Kerberos Authentication Service and Ticket Granting Service event logging, specifically tracking Event IDs 4768 and 4769. To maintain a non-disruptive, controlled scope, a strict constraint is established: we will not interact with or target the Domain Controller itself. The entire objective remains framed strictly as an identity relationship problem, focusing on how authorization paths are structured within the domain.
