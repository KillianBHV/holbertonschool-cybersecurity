To reach Thornbury’s database server via identity paths rather than system exploitation, we enforce an identity-first verification framework to evaluate all recovered material.

## Identity Verification and Non-Plaintext Authentication Flow
Recovered cryptographic material has a strictly defined use centered on evaluating direct authentication viability before any parsing or cracking. Upon collection, we validate the recovered identity against domain groups, roles, ACLs, and delegation paths to map its relationship to Thornbury's database server. If this validation confirms effective administrative rights, the material is utilized directly via Pass-the-Hash (PtH) or Pass-the-Ticket (PtT) techniques to establish an authorized session. Plaintext recovery is treated as secondary; we only evaluate if the material itself supports an authorized authentication path.

## Cracking Priority Rubric and Stopping Rule
Cracking is executed only as a last resort when direct non-plaintext authentication paths are unavailable. We score remaining hashes by weighing expected access value against cracking effort. Expected value depends on the identity’s proximity to Thornbury’s database server, while effort is estimated by password entropy and hash type. We explicitly skip hashes whose computed time cost outweighs their access value. Our strict stopping rule dictates that cracking ceases immediately if a hash's time-to-crack estimate exceeds 45 minutes, or if a lower-cost identity path providing equivalent DB access is discovered.

## Domain Controller Records and Constraints
We anticipate that before we perform any active movement, the Domain Controller will record our presence through Kerberos Authentication Service and Ticket Granting Service logs, specifically tracking Event IDs 4768 and 4769. To guarantee safety, we establish a hard constraint: we will not touch or target the Domain Controller. The entire objective remains framed as an identity path problem, focusing solely on who the domain thinks we are.
