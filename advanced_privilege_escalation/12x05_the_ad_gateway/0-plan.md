# Domain Assessment Plan

To model this domain, which has accumulated fifteen years of operational history, we will build a structural model of configuration drift and persistent authorization sédimentation rather than a traditional attack graph. The objective is strictly limited to mapping the structural integrity of the domain's architecture. Enumeration will follow an order based on structural asset types: first, a baseline inventory of user accounts, organizational units (OUs), and native security groups via standard, non-intrusive LDAP queries; second, an analysis of Group Policy Object (GPO) deployments; and finally, the collection of Access Control Lists (ACLs) applied to high-value business assets.
Any attempt to compromise or pursue control of the Domain Controllers is explicitly prohibited and outside the scope of this engagement.
The logical connections or "edges" generated by automated collector tools will be treated purely as abstract structural indicators rather than active paths for exploitation or lateral movement. To evaluate whether a permission or relationship is real before logging it as a systemic finding, we will rely strictly on static administrative analysis:
* For permission-based entries: We will extract the full security descriptor of the target object using native PowerShell tools to manually audit the specific Access Control Entries (ACEs). We will verify whether explicit denegations, conflicting inheritance flags, or nested group filters would functionally block the theoretical privilege in practice.
* For configuration-based entries: We will inspect cross-domain trusts and GPO links directly against the schema definition to ensure the rule represents an active, operational configuration rather than an unlinked, dead artifact.
The failure we are guarding against is scope drift driven by a penetration testing mindset, which improperly shifts focus from structural auditing toward active lateral movement validation. If an identified relationship or permission looks suspect or cannot be verified through static administrative analysis, we will immediately freeze further evaluation of that branch, document the configuration discrepancy for the final architecture report, and move to the next independent organizational unit to maintain a comprehensive, bounded assessment of the environment.
