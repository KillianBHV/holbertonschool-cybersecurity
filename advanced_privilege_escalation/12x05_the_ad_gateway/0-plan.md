# Plan

To model this domain, which has accumulated fifteen years of operational history, we will build a model of sedimentary privilege exposure and trust relationships rather than a simple, linear road map to the Domain Controllers. Enumeration will follow a strict order of increasing privilege and criticality: first, passive mapping of base objects (users, key native groups, computers) via standard LDAP queries; second, targeted extraction of active sessions and Group Policy Objects (GPOs); and finally, the collection of ACLs specific to critical objects.
Attack paths proposed by our graph theory tools (such as BloodHound) will be treated solely as theoretical hypotheses of connectivity. To validate whether an edge is real before spending effort on it, we will apply rigorous technical verification methods:
* For a session edge (HasSession): We will query the remote registry or the print spooler RPC service to confirm the actual presence of tokens or recent user activity on the host, rather than blindly attempting lateral movement.
* For an access control edge (GenericAll, WriteDacl): We will extract the full security descriptor of the target object using tools like PowerView to manually analyze the Access Control Entries (ACEs). We will verify the absence of explicit denegations, conflicting inherited ACEs, or nested group filtering that would invalidate the theoretical link drawn by the graph.
The failure we are guarding against is "tunnel vision" (getting bogged down in a false positive attack vector), which leads testers to blow scope through an obsession with reaching the Domain Controller. If an attractive path turns out to be non-viable, we will immediately pivot to a resilience strategy: we will freeze that branch of the graph, document the link's invalidity for the final report, and re-evaluate adjacent nodes at equivalent privilege levels to uncover alternative paths of least resistance.
